# Dev loops now demand a stable session identity

- Date: `2026-08-31`
- Channel: `nightly`
- Version: `0.1.0-nightly.820.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.820.1

A quiet nightly with a single, focused change to the automaton contract: dev-loop starts can no longer be initiated without a session identifier, closing a gap that could let telemetry and rate-limit buckets drift across concurrent runs.

## 12:35 AM — Mandatory X-Aura-Session-Id on dev-loop starts

The automaton start contract now treats the session identifier as a required field rather than an optional hint, aligning the harness and server with what the model-request path already enforces.

- Promoted aura_session_id from Option<String> to a required String on AutomatonStartParams, so dev-loop bootstrap and continuation requests can no longer be constructed without a stable identifier — matching the model-request contract that rejects missing X-Aura-Session-Id headers. (`c649557`)
- Updated server-side identity validation and dev-loop param assembly to derive the session ID directly from stable_dev_loop_session_id and treat blank strings (not just None) as missing, keeping Cloudflare's (IP, session) rate-limit bucket stable across dev-loop restarts. (`c649557`)
- Refreshed harness identity checks and tests to cover the new non-optional shape, including round-trip coverage through automaton_start_params_to_runtime_request. (`c649557`)

## Highlights

- Session ID is now mandatory for dev-loop starts
- Cleaner automaton start contract in the harness
