# Hosted workspace files reach the IDE preview

- Date: `2026-08-28`
- Channel: `nightly`
- Version: `0.1.0-nightly.810.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.810.1

A focused day for Aura's web preview: the IDE can now browse and read the actual files an agent is editing inside a hosted local Harness, closing a long-standing gap between the generic filesystem endpoint and the agent's real workspace.

## 8:16 PM — File Explorer can browse a hosted Harness workspace

The IDE preview gains first-class access to files inside a hosted local Harness, with a dedicated server route and a reworked File Explorer that reads the agent's real workspace instead of the generic host filesystem.

- New hosted-workspace file handlers on aura-os-server resolve the authoritative Harness workspace path and proxy only workspace-relative reads, with path validation that blocks parent-dir and absolute-path escapes and an explicit project-id check to prevent cross-project instance replay. (`b725c73`)
- File Explorer, Sidekick content and taskbar, IDE view tabs, and the terminal-target hook were rewired around a new hosted-workspace API client so the tree, tabs, and terminal all target the agent's actual workspace in web deployments. (`b725c73`)
- Coverage lands alongside the feature: Rust integration tests for the new handlers plus a Playwright desktop e2e spec (hosted-workspace-files.desktop.spec.ts) and unit tests for the File Explorer state, IDE view tabs, and terminal-target hook. (`b725c73`)

## Highlights

- File Explorer now reads the live hosted Harness workspace
- New server handlers safely proxy workspace-relative reads
- Desktop e2e coverage for hosted workspace browsing
