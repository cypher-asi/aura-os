# Native desktop task notifications land on Mac, Windows, and Linux

- Date: `2026-07-08`
- Channel: `nightly`
- Version: `0.1.0-nightly.745.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.745.1

Today's nightly is focused on a single, substantial shipment: Aura's desktop app can now raise real OS-level notifications when tasks change state, backed by a new notification bridge in the Rust shell and matching preference and toast surfaces in the interface.

## 6:21 PM — Native task notifications across macOS, Windows, and Linux desktops

The desktop app gains a full native notification pipeline for task events, wired end-to-end from the Rust shell to a new in-app toast and preferences UI.

- Task events now raise real OS notifications on all three desktop platforms: macOS uses the UserNotifications framework (including foreground presentation), Windows goes through WinRT toast APIs via new Data_Xml_Dom and UI_Notifications features, and Linux/other Unix desktops use Freedesktop/XDG notifications over D-Bus through a pinned notify-rust 4.12. (`400777a`)
- A new desktop notification bridge in aura-os-desktop (notifications.rs, events.rs, ui/runtime.rs) connects task activity from the shell to the OS notification center and logs each native delivery for debugging. (`400777a`)
- The interface ships a matching in-app experience: a new Toast component and store, a use-task-notifications hook, a notification classifier, and an expanded Notifications settings section so users can tune what gets surfaced. (`400777a`)
- Notification permission is now requested at desktop startup, with the prompt automatically skipped under CI and a Playwright e2e smoke added to guard the flow. (`400777a`)

## Highlights

- Native task notifications on macOS, Windows, and Linux
- In-app toast surface and notification preferences
- Permission requested at startup, suppressed in CI
