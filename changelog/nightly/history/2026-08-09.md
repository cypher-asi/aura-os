# Clone remote agents into the local harness

- Date: `2026-08-09`
- Channel: `nightly`
- Version: `0.1.0-nightly.783.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.783.1

Today's nightly introduces a single, focused capability: you can now take a remote swarm agent and spin up a local copy of its configuration without disturbing the original. The change spans a new server endpoint, network client support, and a dedicated UI flow in the Agent Info panel.

## 9:19 AM — Clone a remote agent to a local one

A new end-to-end flow lets users fork a remote swarm agent's portable configuration into a fresh local agent, with an explicit contract about what gets copied and what doesn't.

- Added a dedicated clone endpoint on the agents API that projects a remote swarm agent's role, personality, system prompt, skills, and icon into a new local agent, while guaranteeing the source is never mutated (source_preserved is an invariant of the handler, not a best-effort promise). (`6ad975e`)
- Introduced a Clone Agent to Local modal in the Agent Info panel and Sidekick taskbar, so users can name the new local agent (defaulting to a `<source>-local` name) and see the copy report before committing. (`6ad975e`)
- The response returns a structured copy report listing which fields were copied vs. deliberately left behind, so users don't mistake a configuration clone for a transfer of secrets or runtime state. (`6ad975e`)
- Extended the Rust network client and TypeScript agents API with matching clone-to-local calls, backed by new server and UI tests covering the happy path and modal behavior. (`6ad975e`)

## Highlights

- Clone a remote agent into a local one from the Agent Info panel
- New server endpoint preserves the source and returns an explicit copy report
- Available across Desktop builds for Linux, macOS, and Windows
