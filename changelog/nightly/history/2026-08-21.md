# Smarter default-browser detection on Desktop

- Date: `2026-08-21`
- Channel: `nightly`
- Version: `0.1.0-nightly.796.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.796.1

A quiet nightly focused on making Desktop's Advanced settings behave correctly across environments. The single shipped change swaps hard-coded platform checks for capability detection, so browser-related preferences appear only where they actually work.

## 8:01 AM — Advanced settings gate browser options by runtime capability

The Desktop Advanced settings pane now decides whether to show browser-related controls based on what the runtime can actually do, rather than assuming based on platform, with supporting fixes in the shared API layer.

- Advanced settings in Desktop now detect browser-related capabilities at runtime before rendering their controls, so options only appear when the underlying environment actually supports them instead of relying on brittle platform assumptions. (`8fd84e3`)
- Reworked the desktop API bridge and core client so same-origin requests stay routed locally even when a custom API host origin is configured, preventing desktop-only endpoints from being misrouted to a remote host. (`8fd84e3`)

## Highlights

- Desktop Advanced settings now gate browser options by capability
- Same-origin API requests stay local even with a custom host configured
