# Reliable cleanup for swarm-hosted agents

- Date: `2026-06-19`
- Channel: `nightly`
- Version: `0.1.0-nightly.696.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.696.1

A focused server-side fix today closes a long-standing gap in how remote, swarm-hosted agents get torn down — making status probes and agent deletion behave predictably even when the swarm gateway needs an extra step to stop a running agent.

## 1:02 AM — Swarm agent deletion now drives the gateway to completion

Deleting an agent that lives on the swarm now properly tears it down through the swarm gateway, with retry-and-stop handling so status probe agents no longer linger as orphans.

- Agent delete on the server now detects swarm-hosted agents by machine type and routes the teardown through the configured swarm gateway, returning a clear service-unavailable error when SWARM_BASE_URL is missing instead of silently leaving remote state behind. (`90752cd`)
- The swarm delete path now recognizes 409 "needs stop" responses, issues a stop call, and retries the delete up to twelve times with a 5-second backoff before surfacing a bad-gateway error — so probe agents that are still running get cleaned up instead of failing outright. (`90752cd`)
- Added a remote-delete integration test suite and expanded the status-probe runner with its own test coverage, locking in the new teardown behavior used by observability probes. (`90752cd`)

## Highlights

- Remote swarm agents now delete cleanly via the gateway
- Stuck agents are stopped and retried before deletion fails
- New tests cover remote-delete and status probe flows
