# Loop Engineering runs now seed their own tasks

- Date: `2026-06-20`
- Channel: `nightly`
- Version: `0.1.0-nightly.703.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.703.1

A small but meaningful server-side change today: starting a Loop Engineering run now automatically materializes a task tied to the run, so work shows up in the task list instead of living only inside the loop.

## 9:33 AM — Loop Engineering runs seed a tracked task on start

Kicking off a Loop Engineering run now ensures a corresponding task and parent spec exist, with the new task pushed to clients in real time.

- When a Loop Engineering run starts, the server now derives a title and description from the run's goal and creates a 'ready' task under a dedicated 'Loop Engineering' spec, reusing an existing task if one already matches so repeated starts don't duplicate work. (`0b49aab`)
- Newly seeded tasks are assigned to the resolved agent instance and broadcast via the task-saved channel so the interface picks them up live without a manual refresh. (`0b49aab`)
- Supporting plumbing in the harness WebSocket bridge, automaton protocol, and the interface loop API client keeps the start-loop flow consistent end to end. (`0b49aab`)
