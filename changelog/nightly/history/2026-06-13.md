# LLM-powered status investigations land in observability

- Date: `2026-06-13`
- Channel: `nightly`
- Version: `0.1.0-nightly.661.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.661.1

Today's nightly is a focused observability upgrade: when status probes detect a problem, an LLM-backed investigator now produces structured incident reports that flow through the public status page and into every release pipeline.

## 8:38 PM — LLM investigation reports for status incidents

A new investigator pipeline turns failing status probes into structured, model-generated incident reports surfaced across the marketing status page and release workflows.

- Added an end-to-end status investigator that runs after probes, calls a configurable Anthropic-compatible model, and writes structured investigation reports alongside check results, governed by a new status policy and expectations config. (`7226b56`)
- Wired the new status:investigate step into the Aura observability workflow as well as both nightly and stable desktop release pipelines on macOS aarch64, uploading investigation artifacts next to existing observability checks and logs. (`7226b56`)
- Reworked the marketing StatusView and its API layer to ingest and render investigation findings, with a substantially expanded UI, styles, and tests for the new report surface. (`7226b56`)
- Updated the Aura feature health doc and status snapshot builder to incorporate investigations into the published health story, so operators and users see the same enriched signal. (`7226b56`)

## Highlights

- Automated LLM investigation reports for failing status checks
- Investigations wired into nightly and stable desktop release pipelines
- Public Status view redesigned to surface investigation findings
