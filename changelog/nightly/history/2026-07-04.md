# Desktop shell stops masquerading as a mobile client

- Date: `2026-07-04`
- Channel: `nightly`
- Version: `0.1.0-nightly.726.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.726.1

A small but high-impact fix restores the correct desktop experience on Mac, Windows, and Linux, where the loopback-served shell had been misidentified as a native mobile runtime and pushed users into the wrong UI.

## 5:11 AM — Desktop runtime detection no longer treats the Tauri shell as mobile

Because the desktop app is served from a loopback origin, runtime detection was classifying it as a native mobile client and swapping in the wrong login view, shell, and host resolution. Presence of the Tauri/desktop bridge globals now correctly identifies it as a desktop client.

- Desktop builds on Mac, Windows, and Linux are once again rendered with the desktop UI instead of falling through to the mobile login and shell, by short-circuiting isNativeRuntime() when a desktop bridge global (__AURA_BOOT_AUTH__, __TAURI__, or __TAURI_INTERNALS__) is present on window. (`cf021f8`)
- Capability and host-config detection stop demanding an explicit host origin on desktop, while Capacitor and loopback mobile-dev webviews continue to be treated as native runtimes. (`cf021f8`)

## Highlights

- Desktop app no longer flips into the mobile login and shell
- Tauri bridge globals now authoritatively mark the runtime as desktop
