# A self-healing observability pipeline for Aura

- Date: `2026-06-14`
- Channel: `nightly`
- Version: `0.1.0-nightly.664.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.664.1

Today's nightly is almost entirely an observability platform push: Aura's status checks gained richer evidence packets, automated source discovery, gated AI-driven repair workflows, and a learning loop that captures lessons across every release. CI guardrails for release history publishing rounded out the day.

## 4:15 AM — Structured evidence packets for status investigations

Failed observability checks now produce redacted, contract-aware evidence packets with verifier guidance surfaced through the marketing status view.

- Investigations now emit a structured 'aura-observability-investigation-packet' with feature metadata, check contract, sibling-failure patterns, missing required evidence, source hints, and a deterministic reproduction command — all routed through a new redaction layer before leaving the runner. (`64c1782`)
- Packets gained a verifier-context companion that correlates same-message siblings, flags likely shared-dependency failures, validates against the check expectation contract, and includes inline source excerpts alongside hints. (`0cefae5`)
- Verifier guidance is now exposed through the marketing status API and StatusView, giving the public status surface a path to show why a check failed instead of just that it failed. (`9931666`)
- Added an end-to-end test that exercises the investigations runner against a fake LLM endpoint, locking in the packet and verifier-context payload shape. (`fec3a7a`)

## 8:04 AM — Gated AI repair loop with automatic dispatch

A new repair pipeline can investigate failing checks, propose patches with confidence gating, and auto-dispatch a PR-opening workflow from the observability job.

- Investigation context now includes a dedicated source-discovery module that ranks candidate code paths, surfaces recent changes, and feeds both evidence packets and verifier probes with concrete file targets. (`76da587`)
- Shipped a gated repair loop behind a new aura-observability-repair workflow: it runs probes, investigates failures, and can apply a model-proposed unified diff, open a PR, and run allowlisted verification commands — all guarded by path-prefix and apply/PR toggles. (`8d605c0`)
- The main observability workflow now plans and auto-dispatches that repair workflow when investigations clear a configurable minimum-confidence threshold, with PR creation and verification enabled by default for qualifying failures. (`6efed69`)

## 12:21 PM — Suspect-change attribution and a cross-release learning loop

Investigations now pinpoint likely culprit commits, and a new learning step captures lessons from every nightly, stable, and observability run.

- Added a suspect-change analyzer that walks git history for candidate paths, scores commits by path overlap, eval-term matches, and whether they landed between the last passing and current failing run, then attaches PR metadata to the top suspects in both investigation and repair contexts. (`0970cd3`)
- Introduced a status-lessons module and 'status:learn' step wired into the observability, repair, nightly-release, and stable-release workflows so each run produces durable lessons artifacts uploaded alongside checks and investigations. (`0276ee1`)

## 8:25 PM — Release history publishing guard in CI

Tightened the nightly and stable release workflows so release-history publishing only runs under the expected conditions.

- Added a guard around the release-history publishing step in both release-nightly and release-stable workflows to prevent it from running on incomplete or unintended jobs. (`aee54ab`)

## Highlights

- Investigations now ship structured evidence packets with verifier guidance
- Gated AI repair loop can auto-dispatch and open PRs for failing checks
- Suspect-change detection plus a learning loop across nightly and stable releases
- Release history publishing in CI is now guarded against bad runs
