# Feature health and runtime evidence become separate signals

- Date: `2026-06-15`
- Channel: `nightly`
- Version: `0.1.0-nightly.665.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.665.1

Today's nightly reworks how Aura's status system reasons about feature health. Checks now declare which runtime they actually exercised — production API, desktop release, or local dev — so the public status dashboard can tell deployment evidence apart from end-to-end product proof.

## 1:40 AM — Status dashboard separates feature health from runtime evidence

The observability stack and marketing Status view were reworked so each check declares the runtime it ran against, letting the dashboard show product health and deployment health as distinct signals.

- Status checks now carry an explicit runtime axis (production-api, desktop-release, local-dev) alongside the feature they cover, and the Status view groups checks by feature while labeling the runtime on each row so deployed-API noise no longer masks real product regressions. (`6b9c8b0`)
- Media Generation health is now sourced from the desktop-release lane where the bundled harness actually exists; the public observability workflow keeps its production-auth media probe but treats it as informational rather than a pass/fail product proof. (`6b9c8b0`)
- Nightly and stable desktop release workflows on macOS, Windows, and Linux now run an image-generation-stream check as part of the desktop observability suite, and tag their runs with AURA_STATUS_RUNTIME_ENVIRONMENT=desktop-release so artifacts are attributed to the right lane. (`6b9c8b0`)
- The feature-health policy gained dedicated tests and updated investigator, repairer, and learning runners so informational runtime evidence is preserved through repair dispatch without falsely flipping a feature green or red. (`6b9c8b0`)

## Highlights

- Status checks now distinguish feature health from the runtime that produced the evidence
- Media Generation proof is anchored to the desktop-release lane, with production-auth checks demoted to informational
- Desktop release workflows on macOS, Windows, and Linux now exercise image-generation-stream end-to-end
