# Signup credit grants self-heal on session refresh

- Date: `2026-05-20`
- Channel: `nightly`
- Version: `0.1.0-nightly.544.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.544.1

A small but high-impact server fix shipped today: users whose signup credit grant silently failed at login — leaving them stranded at zero credits — will now have it automatically retried as their session refreshes.

## 3:07 PM — Automatic recovery for failed signup credit grants

The session endpoint now retries the signup credit grant so users whose initial grant failed against z-billing no longer stay permanently stuck at 0 credits.

- Signup credit grants are now retried on GET /api/auth/session (app boot and the 20s keepalive) and on token validation, rescuing users whose original grant failed because z-billing was unreachable at login — without which daily and monthly grants stay blocked behind signup_grant_at. (`0eb9502`)
- Retries are deduped via an in-memory DashSet so each user only hits z-billing once per server process, relying on the endpoint's idempotency to make already-granted users a no-op and keep keepalive traffic cheap. (`0eb9502`)

## Highlights

- Stuck-at-zero-credits accounts recover automatically
- Idempotent retry deduped per server process to spare z-billing
