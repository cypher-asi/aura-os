# Steadier status page freshness signals

- Date: `2026-06-16`
- Channel: `nightly`
- Version: `0.1.0-nightly.674.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.674.1

A focused tune-up to Aura's public status page and its observability probes, raising the noise floor on freshness checks so transient snapshot lag no longer trips false alarms.

## 7:26 AM — Status page freshness thresholds relaxed to cut false alarms

Tuned the public status page and its evaluation probes so brief snapshot staleness no longer flips features into a degraded state.

- Raised snapshot freshness tolerances on the public status checks, lifting the max snapshot age from 180 to 300 minutes and standardizing per-check stale windows at 30 minutes so short publishing delays no longer mark core API, auth, and system-info as stale. (`5a0475f`)
- Reclassified the published-observability-snapshot check as informational with a 360-minute stale window, and added policy test coverage confirming features stay operational when only that snapshot's freshness metadata fails. (`5a0475f`)
- Updated the marketing StatusView with new styling and rendering for the informational-impact state so users see a clearer, non-alarming indicator when a check is advisory rather than outage-worthy. (`5a0475f`)
- Shifted the AURA Observability workflow cron from the top of every other hour to :17 past, reducing contention with other scheduled jobs that kick off on the hour. (`5a0475f`)

## Highlights

- Status page tolerates short snapshot lag without flapping
- Published snapshot freshness demoted to informational
- Observability probe cadence offset to avoid collisions
