# Skill delegation, project workspace rebinding, and calmer observability

- Date: `2026-07-21`
- Channel: `nightly`
- Version: `0.1.0-nightly.769.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.769.1

Today's nightly threads together three focused changes: custom Skills can now target a specific collaborating agent with proper runtime safeguards, project workspaces can be relinked to a local folder on each Desktop machine (including via an agent tool), and the AURA observability workflow settles into a quieter twice-daily cadence.

## 3:12 AM — Custom Skills can bind to a collaborating agent

Skills now support delegating to a specific project agent, with server-side guards that keep cross-agent turns from being routed to stopped runtimes.

- Skill creation and editing modals gained a new agent target field so authors can bind a custom Skill to a specific collaborating agent within the project, backed by end-to-end coverage for the skill-agent binding flow. (`edd5454`)
- Added a cross-agent runtime gate on the server: when a model tool triggers a delegation, Aura now checks the target agent's remote VM state and returns a tool-visible "target agent is not available for delegation" error unless the remote is running or working. (`edd5454`)
- Harness proxy create/update paths validate project membership, capability, and runtime availability when a Skill is pointed at a collaborating agent, with new integration tests covering the create and update flows. (`edd5454`)

## 4:07 AM — Relink a project to a local workspace folder

Project Settings and the agent tool surface both gained a way to point a project at a specific local folder on the current Desktop machine, or clear the override.

- Project Settings now exposes a folder picker for attaching a per-machine local workspace path, backed by a new PATCH-style API that accepts an absolute path or null to clear the override. (`88258ba`)
- Agents get a new platform-trust set_project_workspace tool, scoped to the bound project, so an assistant can attach or clear the local workspace folder on the user's Desktop machine through the standard tool permission catalog. (`88258ba`)
- FolderPickerField and ProjectSettingsModal were reworked with refreshed styles and substantially expanded tests to cover the relink and clear flows. (`88258ba`)

## 4:33 PM — AURA observability workflow moves to a 12-hour cadence

The observability GitHub Actions workflow now runs twice a day instead of every two hours, and no longer auto-chains off Desktop release workflows.

- Scheduled cron changed from every 2 hours to every 12 hours, cutting routine observability runs by ~6x while preserving manual workflow_dispatch and the gated repair path. (`a6eda11`)
- Removed the workflow_run trigger that fired observability after Desktop Nightly and Stable releases, along with its success-conditional job guard, simplifying when the job runs. (`a6eda11`)

## Highlights

- Custom Skills can now delegate to a specific project agent
- New set_project_workspace tool and Project Settings folder relinking
- Observability workflow moves from every-2h to every-12h
