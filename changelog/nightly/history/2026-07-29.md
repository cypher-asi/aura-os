# Safe Workspace comes to hosted Harness deployments

- Date: `2026-07-29`
- Channel: `nightly`
- Version: `0.1.0-nightly.778.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.778.1

A focused nightly that extends Aura's Safe Workspace isolation model beyond desktop projects, so hosted-local Web projects running on a capable Harness can finally opt into per-session worktrees — with a clean fallback for older deployments.

## 3:34 AM — Safe Workspace on hosted Harness with capability-gated fallback

Safe Workspace isolation is now available for hosted-local Web projects, routed through the Harness lifecycle when it advertises support and hidden otherwise.

- Hosted-local Web projects can now execute chat turns inside an isolated Safe Workspace via a new hosted-Harness code path, alongside the existing desktop server-owned flow, by resolving an explicit execution-workspace authority (Aura server, hosted Harness, or Swarm) per request. (`28c45cb`)
- Older hosted Harness deployments fail closed: the server checks a `safe_workspace: true` capability before accepting a safe turn, returns a clear 'not supported by the currently deployed hosted harness' error otherwise, and the AgentChatPanel hides the Safe Workspace control when the capability is absent. (`28c45cb`)
- Remote/Swarm agents are explicitly rejected with a dedicated 'not yet available for remote agents' error, keeping the existing execution model intact for those sessions. (`28c45cb`)
- Documented that foreground child agents inherit the parent's resolved project path, so a safe parent keeps its spawned children in the same session worktree without changes to spawn or streaming behavior. (`28c45cb`)

## Highlights

- Safe Workspace now runs on hosted Harness
- Graceful fallback when the Harness is too old
- Spawned child agents inherit the parent's safe worktree
