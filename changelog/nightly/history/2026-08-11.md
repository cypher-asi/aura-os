# Microsoft Edge discovery lands for Windows browser automation

- Date: `2026-08-11`
- Channel: `nightly`
- Version: `0.1.0-nightly.787.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.787.1

A focused nightly centered on making Aura's embedded browser work out of the box on Windows. The CDP backend now finds Microsoft Edge through the Windows registry, validates configured executables before launch, and surfaces a clear, actionable error when no supported browser can be found.

## 1:27 PM — Microsoft Edge discovery on Windows for the CDP browser backend

Aura's headless browser can now locate Microsoft Edge automatically on Windows, and failures to start any supported browser now return a structured, user-actionable error.

- Windows builds can now discover Microsoft Edge automatically through a new windows-registry-backed lookup in the CDP backend config, so users no longer need to hand-set an executable path when only Edge is installed. (`9f93482`)
- Browser launches now pre-validate that a configured executable actually exists on disk and annotate downstream chromiumoxide failures with the specific launch target, making misconfigured BROWSER_EXECUTABLE_PATH values far easier to diagnose. (`9f93482`)
- When no supported browser can be started, the server REST layer now returns a 503 with a dedicated browser_launch_failed code and a message that explicitly names Microsoft Edge, Google Chrome, and Chromium, and points operators at BROWSER_EXECUTABLE_PATH for managed installs. (`9f93482`)
- The Desktop BrowserInstance component and its tests were updated alongside the backend change to reflect the new error surface for launch failures. (`9f93482`)

## Highlights

- Microsoft Edge auto-discovery on Windows via the registry
- Actionable browser_launch_failed errors that name Edge, Chrome, and Chromium
- Safer CDP launches with pre-flight executable validation
