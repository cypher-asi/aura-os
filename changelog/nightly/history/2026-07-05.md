# Workspace access gating and web fallbacks across chat surfaces

- Date: `2026-07-05`
- Channel: `nightly`
- Version: `0.1.0-nightly.730.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.730.1

Today's nightly centers on making Aura behave predictably when the desktop bridge or a remote workspace isn't fully available: build tools now gate cleanly on workspace access, browse-only remote sessions can't kick off automations they can't finish, and the chat history sidebar gets a brief, reverted experiment in richer row context. E2E onboarding coverage was hardened alongside.

## 9:04 AM — Chat history rows briefly gained an agent/project subtitle, then reverted

The chat app left panel experimented with a secondary line naming the owning agent and project, then rolled back to a title-only row while keeping the labeled agent avatar.

- Added a renderRowDetail hook to SessionsList and used it in ChatAppLeftPanel to show 'Agent · Project' under each session title, plus an aria-labeled avatar wrapper identifying the owning agent. (`154ed37`)
- Reverted the secondary detail line minutes later to keep chat history rows title-first, retaining only the agent-labeled avatar for context. (`495417a`)

## 11:52 AM — Automation and build tools now gate on workspace access

A new workspace-access resolver decides when local or remote workspaces are actually usable, and the AutomationBar, Sidekick taskbar, chat input, and Project Files view now disable build tools with a clear reason when they aren't.

- Introduced shared/lib/workspace-access to classify workspace availability from terminal target and the linkedWorkspace capability, with dedicated tests. (`6edb47d`)
- AutomationBar, SidekickTaskbar, ChatInputBar and ProjectFilesView now disable Play, Loop, and build actions when the workspace is loading or unreachable, surfacing tooltips like 'Build tools for local workspaces are available in Aura Desktop' on the web. (`6edb47d`)
- Agent Environment's status card now shows 'Available in Aura Desktop' instead of an empty dash when a local workspace path isn't reachable from the current runtime. (`6edb47d`)

## 7:07 PM — Web workspace dead ends and browse-only remote starts fixed

A large reliability push routes web users away from unusable local workspace flows, prevents browse-only remote agents from kicking off automations they can't run, and stabilizes the onboarding eval against Stats overflow.

- AgentChatPanel, ProjectMainPanel, ExecutionView, and ProjectWorkView now resolve workspace access before wiring the terminal target, so web sessions no longer land on empty terminals or dead-ended IDE tabs when the desktop bridge is missing. (`9bd2075`)
- Threaded workspaceToolsEnabled and a workspace-scoped remote agent instance id through the chat stream and loop-control hooks so tool calls and loops only start when the workspace is truly ready. (`9bd2075`)
- Browse-only remote agents can no longer start automations: AutomationBar, SidekickTaskbar, TaskOutputPanel and AgentChatPanel now block starts when the remote workspace isn't attached, backed by a new AgentChatPanel test suite. (`b84276a`)
- Stabilized the core browser smoke eval by accepting Stats as either an inline button or an overflow menuitem, and added a helper that opens the More menu when Stats collapses at narrow panel widths. (`f69196e`)

## Highlights

- Workspace-aware gating for automation and build tools
- Web sessions no longer dead-end into missing local workspaces
- Browse-only remote agents blocked from starting automations
- Onboarding eval suite made resilient to Stats overflow
