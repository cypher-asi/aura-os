# Chat session lifecycle gets a memory leak fix

- Date: `2026-09-10`
- Channel: `nightly`
- Version: `0.1.0-nightly.830.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.830.1

A focused server-side reliability change for chat: idle harness connections and orphaned replay handles are now actively reclaimed, and cancelled turn-slot waiters properly release their reservations. Desktop artifacts for Linux, macOS, and Windows shipped alongside on the nightly channel.

## 9:18 AM — Reclaim idle chat sessions and cancelled turn-slot reservations

The chat server now evicts unused harness connections and stale replay handles before opening new ones, and cancelling a queued turn correctly frees its slot.

- Chat sessions are tracked in a dedicated registry with a last_used_at timestamp, and new sessions now call make_room_for_chat_session so only unborrowed, idle entries are evicted while in-flight and queued turns stay intact. (`4c07a2a`)
- Turn-slot acquisition now reserves its counter slot before awaiting the mutex, so a caller that is cancelled while queued releases its reservation instead of leaving the queue counter permanently inflated — covered by a new regression test. (`4c07a2a`)
- Session reuse refreshes last_used_at on every hit, keeping active conversations out of the idle-eviction path while genuinely stale replay handles become eligible to be dropped. (`4c07a2a`)
- Render deployment docs were updated to reflect the new chat-session lifecycle behavior for operators. (`4c07a2a`)

## Highlights

- Idle chat harness connections are now reclaimed
- Cancelled turn-slot waiters release their queue slots
- Nightly desktop builds published for Linux, macOS, and Windows
