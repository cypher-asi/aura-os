# Pay-per-call x402 LLM endpoint lands with hardened billing

- Date: `2026-06-09`
- Channel: `nightly`
- Version: `0.1.0-nightly.633.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.633.1

Today's nightly opens up an x402-protected public chat completions endpoint, letting external clients pay per request to talk to Aura's models. A follow-up tightens how the server connects to the z-billing service so usage settlement can't be pointed at unsafe URLs.

## 9:25 PM — x402-paid public chat completions endpoint

Aura's server now exposes an x402-protected public LLM router so third-party clients can pay per request to call hosted models, with full configuration over price, models, network, and facilitator.

- Added `POST /api/public/x402/v1/chat/completions` and `GET /api/public/x402/v1/models` as a new public surface, implementing the x402 protocol directly at the Axum boundary since reference middleware only targets TS/Go/Python. (`c0684ba`)
- Defaults to the `upto` x402 scheme on Base Sepolia USDC with a $0.02 per-request ceiling, settling actual token usage against z-billing quotes via the new `LlmUsageQuote` client path. (`c0684ba`)
- Operators can tune the endpoint through a new env surface — `AURA_X402_PAY_TO`, `AURA_X402_CHAT_PRICE`, `AURA_X402_MODELS`, `AURA_X402_MAX_TOKENS`, `AURA_X402_FACILITATOR_URL`, `AURA_X402_NETWORK`, and related knobs — documented in the README. (`c0684ba`)
- Request handling enforces guardrails for paid traffic: max 64 messages, 32k chars per message, 64k total, a configurable `max_tokens` cap, and a 120s default completion timeout. (`c0684ba`)

## 8:40 AM — Billing client rejects unsafe service URLs

The z-billing client now validates its configured base URL before issuing any request, closing off SSRF-style misconfigurations against the new x402 settlement path.

- Service URLs are now parsed and joined through `url::Url` instead of string concatenation, and must be HTTPS pointing at a public host; HTTP loopback is allowed only in debug/test builds. (`46c9194`)
- Private, loopback, link-local, broadcast, unspecified, and `localhost`-style hosts are rejected, as are URLs that embed userinfo, surfaced through a new `BillingError::InsecureServiceUrl` and `InvalidServiceUrl` errors. (`46c9194`)

## Highlights

- New x402 public LLM endpoint with on-chain micropayments
- Billing client now rejects insecure or private service URLs
- Configurable model allowlist, price ceiling, and facilitator for x402
