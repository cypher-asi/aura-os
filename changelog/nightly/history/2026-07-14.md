# Project-scoped agent memory lands

- Date: `2026-07-14`
- Channel: `nightly`
- Version: `0.1.0-nightly.761.1`
- Release: https://github.com/cypher-asi/aura-os/releases/tag/v0.1.0-nightly.761.1

Today's nightly introduces per-project scoping for agent memory, giving each agent a cleaner boundary between what it remembers globally and what belongs to a specific project. The change threads a project_id through the chat stack, the harness memory proxy, and the Agent Info panel's Memory tab.

## 11:31 PM — Scoped memory controls in the Agent Info panel

Agents can now read, write, and surface memories scoped to a specific project, with the routing wired end-to-end from the interface down through the harness memory proxy and self-improvement handlers.

- Reworked the Memory tab in the Agent Info panel with a substantially expanded UI and preview surface so users can browse and manage memories scoped to the current project rather than a single global bucket. (`c2e74a6`)
- Threaded project_id through the agent chat routes, installed-tools context, and the harness memory proxy so memory reads/writes and tool endpoints carry the active project scope instead of defaulting to agent-wide state. (`c2e74a6`)
- Self-improvement proposals now accept a project_id query parameter and append it to the propose endpoint, so learning suggestions are attributed to the project they originated from. (`c2e74a6`)
- Updated the shared memory API client, types, and harness proxy tests to cover the new scoped routes, tightening confidence that project-scoped memory behaves consistently across the server and interface. (`c2e74a6`)

## Highlights
